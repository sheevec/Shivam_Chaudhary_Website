The problem

Citizens Bank's fraud operations needed a decisioning layer that could prioritise genuinely suspicious transactions without overwhelming investigation teams with low-value alerts.

Every extra false positive meant a blocked customer and analyst time; every missed fraud meant a loss. The system had to score each payment in real time and let the business tune that trade-off.

Architecture

How data moves through the system, stage by stage, plus the services that run across every stage.

Ingestion
Transaction API → Apache Kafka
  • 20M+ events a day on a partitioned transactions topic
Features
PySpark Structured Streaming
  • Velocity: counts and sums over 1h / 6h / 24h windows
  • Merchant risk: Bayesian-smoothed historical fraud rate
  • Amount anomaly: z-score against the user's 90-day baseline
  • Geographic velocity: haversine distance and implied speed
Feature store
Redis (hot) · BigQuery (cold)
  • Cached feature vectors keep the hot path sub-millisecond
Scoring
XGBoost ensemble on Vertex AI
  • Isolation Forest anomaly fallback
  • Calibrated probability outputs
Decision
Threshold router
  • BLOCK at score ≥ 0.85
  • REVIEW between 0.55 and 0.85
  • PASS below 0.55
Action

MonitoringPrometheus + Grafana: latency, drift, throughput
PlatformGCP: GKE, Cloud Run, Vertex AI

Key engineering decisions

The choices that make the system reliable, not just fast.

Thresholds as business levers

BLOCK and REVIEW cut-offs are configuration, so fraud teams can trade recall for analyst workload without a redeploy.

Temporal holdout, not random splits

The model is evaluated on the most recent 14 days so time-correlated features cannot leak future information.

Built for extreme imbalance

Fraud is about 0.3% of transactions; scale_pos_weight and precision-recall metrics keep the model honest where accuracy would not.

Precomputed features on the hot path

Window aggregates are computed in streaming and cached in Redis, so scoring never recomputes history inside the 50 ms budget.

Streaming velocity features

def _velocity_window(seconds: int) -> Window.WindowSpec:
    """Return a range-based window partitioned by user, looking back `seconds`."""
    return (
        Window.partitionBy("user_id")
        .orderBy("_ts_unix")
        .rangeBetween(-seconds, 0)
    )

w1h = _velocity_window(_WINDOW_1H_SECONDS)
w6h = _velocity_window(_WINDOW_6H_SECONDS)
w24h = _velocity_window(_WINDOW_24H_SECONDS)

df = (
    df
    .withColumn("tx_count_1h", F.count("transaction_id").over(w1h).cast(IntegerType()))
    .withColumn("tx_sum_1h", F.sum("amount").over(w1h).cast(DoubleType()))
    # … 6h windows …
    .withColumn("tx_count_24h", F.count("transaction_id").over(w24h).cast(IntegerType()))
)
